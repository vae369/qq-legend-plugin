# 2026-11-12

## 传奇 QQ 插件：旧 MYPCQQ 接口迁移到纯白铃 SDK 写法（方案 A：保留 .NET Framework 工程）

用户确认的三项决策：保留现有工程换接口 / openid 作用户主键 / 缺失能力降级。

### 改动
- 新增 `Qiancao/QiancaoSdk.cs`：移植 SDK 的 QcApi 常量、MessageInfo、Bot（SendMessageEx/GetUserName/OutLog/CallRaw/UserKeyOf/ParseMessage）。
  .NET Framework 4.7.2 适配点：委托代替函数指针、自实现 UTF-8 指针转换、JSON 用 System.Web.Extensions 的 JavaScriptSerializer。
- 新增 `Qiancao/QiancaoPlugin.cs`：DllExport(cdecl) 导出 get_plugin_info / onMessagev3 / on_enable / on_disable / on_unload / on_set / set_plugin_path；
  onMessagev3 恒返回 NULL、全 try/catch、按 MsgId 去重、用 cmd→key 还原改名后的指令。
- 新增 `Qiancao/CommandRules.cs`：从 QQMain.cs 的 case/StartsWith 自动提取 215 条规则（180 equals + 35 startswith），fun=下标+1。
- `QQMain.cs`：MQEvent(11 参) → HandleMessage(MessageInfo)；169 处 ApiSendMsg → Bot.SendMessageEx；
  69 处 [Pic,route=] → [image,path=]；[@QQ] → <@openid>；8 处跨群广播收敛为当前群；点赞降级提示；气泡 ID 丢弃。
- `传奇.csproj`：显式 Compile 列表登记三个新文件（该项目漏登记会 CS0246）。
- 工具：`.workbuddy/tools/migrate_qiancao.py`（命令词变更后重跑）、`.workbuddy/backup/QQMain.cs.bak`、`.workbuddy/tools/selftest/`（自测项目）。

### 验证
- `dotnet build -t:Compile -p:PrepareResourcesDependsOn= -p:DisableFody=true`：CoreCompile 通过，0 个新增编译错误（24 个既有警告）。
- 自测 `QiancaoSelfTest.exe`：19/19 PASS（消息帧解析、主键净化、规则表、get_plugin_info JSON、api 2/9/1 参数顺序、onMessagev3 端到端分发、异常兜底）。
- 完整打包在本机 **dotnet SDK 9 的 Core MSBuild 下做不了**：DllExport 1.5.2 的 MSBuild 任务依赖 Microsoft.Build.Utilities.v4.0，
  Core MSBuild 加载报 MSB4062；且 FodyWeavers.xml 写了 Costura 但 packages 无 Costura.Fody（既有缺陷）。需 Visual Studio 的完整 MSBuild 构建。
- 自测假回调必须用 FrameworkCallback 类型的委托取函数指针，否则 Marshal.GetDelegateForFunctionPointer 反查会返回测试委托类型导致 InvalidCastException。

### 待确认 / 风险
- **CLR 自举**：SDK README 判定 DllExport 托管 DLL 是死路（框架 Qt 进程 LoadLibrary 后需 CLR 自举），本方案未经真实框架验证。
- **产物形态**：当前 csproj OutputType=WinExe → 产物 `传奇.MQ.exe`；纯白铃要求插件目录里的 DLL，是否改 Library 未定（改了会失去独立窗体工具）。
- **配置迁移**：config.ini 的「超级管理员」「屏蔽消息群」仍是 QQ 号，需改成 openid；存量 `<QQ号>.ini` 存档不自动迁移，新主键为 `<openid>_<短id>.ini`。
